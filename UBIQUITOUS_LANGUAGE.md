# Ubiquitous Language

> Canonical terms used across Glasswork code, UI, docs, and conversations
> with agents. Use these terms exactly. Aliases listed are explicitly
> rejected — do not use them.

| Term | Definition | Aliases to avoid |
|---|---|---|
| **Vault** | The Obsidian folder Glasswork reads tasks from — specifically, the **vault root**, the top-level directory Obsidian opens when selecting that vault. The task directory lives at `<vault root>/wiki/todo`. The `vault.path` persisted UI state key and the `GLASSWORK_VAULT` environment variable both refer to the vault root. Currently defaults to `%UserProfile%\Wiki`. | folder, directory, repo, store |
| **Task** | A work item represented by one `.md` file in the vault. May have subtasks, notes, Links, due date, and legacy ADO frontmatter during migration. Carries a **Task type** (`task` / `pbi` / `bug`). | item, work item (work item is overloaded — use only when explicitly referring to ADO) |
| **blocked_by** | A generic top-level Task relationship containing the IDs of Tasks that must be considered before the current Task is ready. It is distinct from **Blocked Task** status and `blocked_reason`; it does not itself change the current Task's status. | dependency list, blocked task |
| **Resource Revision** | An opaque, versioned token derived from the exact bytes used for a managed Task read. Clients compare it for equality only; they must not parse its digest format or algorithm. | mtime, file version, content hash |
| **read basis** | The deduplicated set of related Task snapshots and Resource Revisions whose state affected a relation-aware query page's matching decision. | query context, evidence set |
| **Capability discovery** | The read-only MCP handshake that reports the contract version and stable named workflow guarantees currently implemented or explicitly deferred. | feature probe, runtime negotiation |
| **Blocked Task** | A Task whose `status` is **`blocked`** and whose blocker metadata lives in task frontmatter: `blocked_reason`, `blocked_at` (RFC 3339 UTC), and `blocked_from_status` (`todo` or `in-progress`). A Blocked Task stays visible in the Backlog's dedicated blocked surface, but it is never **Ready**, never **In My Day today**, and never suggested as actionable work until resumed or completed. Task-level blocked is independent from blocked Subtasks. | stuck task, paused task |
| **Needs blocker details** | The degraded state for a Blocked Task whose blocker metadata is missing or malformed. The Task still renders in the blocked surface so the user can repair it, but automated resume / status mutation is disabled until repaired. | invalid blocked task, broken blocker metadata |
| **Task type** | The `type` frontmatter field on a task, mirroring ADO work-item types. One of **`task`** (default — an actionable leaf), **`pbi`**, or **`bug`**. Parsed via `GlassworkTask.Types.Normalize` (null / empty / unrecognized ⇒ `task`, case-insensitive); the default `task` is **omitted** on serialize to avoid churning legacy files. Only `pbi` changes behavior (see **PBI**). See ADR 0016. | kind (kind is reserved for **Artifact kind**), category |
| **PBI** | A task with **Task type** `pbi` — a **container** (ADO Product Backlog Item / User Story), not an actionable leaf. Its work surfaces through its child tasks/subtasks. A PBI does **not** self-promote to My Day on its own `due` date (the ADO import stamps a sprint-end due on every PBI). Although a direct pin still participates in My Day membership policy, the My Day view renders a PBI only as a **container card** when it has actionable **Today's subtasks** or **Today's children**; an empty standalone PBI is hidden. See ADRs 0016 and 0017. | epic, story, container (use "PBI" in code/frontmatter; "container" only when contrasting with a leaf in prose) |
| **Bug** | A task with **Task type** `bug` — an **actionable leaf**, identical to `task` for My Day promotion. Named only to mirror ADO's work-item type so imports round-trip. See ADR 0016. | defect, issue |
| **Subtask** | A child step inside a task. Has its own status (`todo`, `in_progress`, `blocked`, `done`, `dropped`), title, optional notes. Lives inline in the parent's `.md` body. | step, todo (step is fine in user copy; subtask is canonical in code) |
| **Subtask row** | The list-item template that renders one subtask in TaskDetail **and** in the today's-subtasks list beneath each promoted parent on My Day. Two interactive hit zones: the **circle glyph** (single-click toggles done) and the **subtask text** (single-click opens `SubtaskDetailDialog`). Hand cursor on the text advertises the affordance. Same model in active and completed lists. See ADR 0004 (interaction) and ADR 0008 (My Day surface). | subtask line, subtask item |
| **Active subtask list** | The `ListView` rendering subtasks not in `done` or `dropped` status. Supports drag-reorder. Each row carries the full action set (My Day toggle, `⋯` More menu). | open subtasks, pending subtasks |
| **Completed subtask list** | The `ItemsControl` inside the `Completed (n)` `Expander`, rendering subtasks in `done` or `dropped` status. Same hit-zone model as active rows. Action set is reduced: no My Day toggle on the row; `⋯` More menu omits "Set due date." Hidden when zero completed. | done list, archive list |
| **Description** | The prose markdown that appears between a task's frontmatter and its `## Subtasks` heading. Answers "what is this task about." Stored on the model as `Task.Description` (was `Task.Body`). Source of `Blurb`. | body, body text (former `Body` was renamed for clarity — see ADR 0002) |
| **Notes** *(task-level)* | The prose markdown in a task's `## Notes` section. Free-form scratch — written by **both humans and agents** (agents gained write access in #71). Rendered via `VaultMarkdownView` in read mode; editable in-app via an explicit read/edit toggle. Distinct from `SubTask.Notes` (per-subtask prose) and from Artifacts (agent-produced deliverables). | task notes, scratch (use "Notes" in UI; "task notes" only when disambiguating from subtask notes in conversation) |
| **Artifact** | An **agent-produced work-product file** attached to a task (plan, design, investigation, draft, summary, generated report) — **any format**, not just markdown. Stored as files in `<vault>/wiki/todo/<taskId>.artifacts/`. The defining axis is **authorship + access**, not format: an Artifact is agent-produced and **read-only in the app**; the vault and Obsidian/agents are the editing surfaces. Distinct from Notes (free-form scratch) and Description (the task's framing prose). Contrast **Attachment** (user-uploaded file — deliberately out of scope). | attachment (attachment implies a *user-uploaded* file, which Glasswork does not support), document, output |
| **Attachment** *(out of scope)* | A **user-uploaded** file on a task. Deliberately **not** a Glasswork concept — Glasswork has no upload affordance and the app stays read-only over task files. Named here only to fix the boundary: agent-produced → Artifact; user-uploaded → Attachment (unsupported). Do not use "attachment" as a synonym for Artifact. | — |
| **Artifact kind** | The per-Artifact render/handling strategy, derived from the file extension: **Markdown**, **Html**, **Image**, **Text** (code/data/plain text), or **Other** (binary or unrecognized — listed by reference, no inline render). Drives which row template renders the Artifact and whether its body is inlined over MCP. Modeled as an `ArtifactKind` discriminator on `Artifact`. | file type, mime type, artifact type (type is overloaded — "kind" is canonical) |
| **Artifacts section** | Collapsible-list surface in TaskDetail rendered beneath Notes. Hidden when zero artifacts. One `Expander` per artifact, ordered by mtime descending; the newest auto-expands and the rest start collapsed. Each header carries a relative-time badge and an "Open in Obsidian" link; the body renders per **Artifact kind** (markdown via Vault Markdown View, images inline, text/code inline, HTML via source/preview, Other by reference only). | artifacts panel, artifacts list, attachments section |
| **Backlink** | An incoming wikilink to a Glasswork task from a vault page **outside** `wiki/todo/` — i.e., any concept, decision, system, incident, or other wiki note that references a task via `[[task-id]]`. The convention lives in [`wiki/concepts/glasswork-task-linking.md`](wiki/concepts/glasswork-task-linking.md) and is mirrored in-app by the Backlinks section. Task-to-task wikilinks (those originating under `wiki/todo/`) are explicitly excluded — those surface as Related, not Backlinks. | reference, mention, incoming link, referenced-from (the UI shows "Backlinks"; use that term in code, copy, and conversation) |
| **Backlinks section** | Collapsible-list surface in TaskDetail rendered beneath Related. Hidden when zero backlinks. One row per linking page, grouped by `BacklinkPageType` (concept, decision, system, incident, other), ordered by page title. Each row shows the page title and a small page-type badge; click opens the page in Obsidian via `obsidian://` URI, gated through `ArtifactLinkPolicy`. Updates live as the vault changes — see `BacklinksWatcher`. | backlinks panel, backlinks list, references section, referenced-from section |
| **Link** | A structured outbound pointer stored in task frontmatter under `links:` with `type`, `value`, and optional `label`. Recognized v1 types are `ado`, `pr`, `incident`, `doc`, `build`, and `other`; unknown types are tolerated as `other`. Distinct from Wiki link (markdown syntax inside rendered prose) and Backlink (incoming reference from another vault page). | hyperlink (too broad), external ref, reference |
| **Links section** | TaskDetail surface that renders a task's Links as read-only rows with type badges and display text. Hidden when `links:` is empty or missing. In v1, Links are edited in Obsidian or YAML, not in-app. | links panel, external refs, references section (reserved for Backlinks-like phrasing) |
| **Automation Review Queue** | The durable review workflow stored under `<vault root>/.glasswork/review-queue.json`. It collects automation-produced Task proposals, source cursors and health, compact 30-day History, and permanent dedupe records. It is a review system, not an Inbox. | inbox, automation inbox, review cache |
| **Review item** | One atomic proposal in the Automation Review Queue. Identified by source meeting/item + Task + proposal type, with a canonical change fingerprint. A Review item is either actionable (`pending`), blocked on revalidation (`needs_refresh`), or terminal (`approved`, `rejected`, `withdrawn`, `expired`). | proposal row, queue row, suggestion |
| **Review source** | A registered automation producer allowed to write into the Automation Review Queue. In v1 the only Review source is `meeting-transcript-sync`, and its allowed proposal-type matrix is code-defined. | feeder, integration, sync job |
| **Pending** | The actionable Automation Review Queue state: the proposal is current and can be approved or rejected. Pending items dedupe by logical identity and expire after 30 days if untouched. | open, waiting |
| **Needs refresh** | The non-actionable active Automation Review Queue state: the proposal is still visible but cannot be approved until revalidated. Rejection or withdrawal remain allowed. | stale, out of date, refresh-needed |
| **Coherent selection** | The set of currently selected Review items for exactly one Task that the Core seam can approve together without conflict. A coherent selection may include multiple meeting-note proposals plus at most one effective state outcome and at most one due-date outcome. | batch, selection set, approve batch |
| **Apply failed** | Retryable Review-item metadata recorded when a selected approval batch could not be written to the target Task. The items stay Pending and carry the last failure code/message instead of moving to History. | partial success, transient failure |
| **Meeting updates** | The managed subsection appended inside task-level Notes for approved meeting-note proposals. Glasswork appends dated entries in meeting-date order beneath the `### Meeting updates` heading and preserves all pre-existing Notes prose outside the appended entries. | meeting log, recap archive |
| **History** *(Review)* | The compact 30-day record of terminal Automation Review Queue dispositions (`approved`, `rejected`, `withdrawn`, `expired`). Distinct from Work Log. | archive, review log |
| **Review source health** | The locally tracked operational state for a Review source: cursor, last success, retained diagnostics, consecutive scheduled failures, and degraded/not-degraded state. Health warnings are operational, not actionable review work. | pipeline health, sync health |
| **Page** | A top-level navigation destination in the app shell (My Day, Backlog, Work Log, Settings). Glasswork keeps "Page" rather than the todo-app convention "Smart List." | screen, view, tab, smart list |
| **Saved Task view** | A named reusable filter that a Page can apply when listing Tasks. Stored in UI State because it describes how tasks are viewed, not the tasks themselves. | saved view, smart list (avoid), filter preset |
| **Ready** | A computed Task signal meaning the task is actionable now: not done, not task-blocked, and not scheduled/deferred to a future `my_day`, `start`, or `defer_until` date. Never stored in frontmatter. A blocked Subtask still affects urgency and the Task card's blocker row, but it does not by itself make the Task a **Blocked Task**. | available, actionable |
| **Urgency score** | A computed ranking signal for Task importance/actionability, combining due date, priority, in-progress state, age, blocked state, and Backlink count. Higher sorts earlier. Never stored in frontmatter. | urgency, actionability score, importance score |
| **My Day** | The default landing page. Shows tasks that are "in My Day today" — see the inclusion rule below. | today, dashboard, home (Home is reserved for the future Home Dashboard) |
| **In My Day today** | A task is in My Day today if **any** of: (a) `task.IsMyDay` (`my_day` frontmatter **equals** today's date — date-scoped per ADR 0013), (b) `task.Due <= today` and not done **and the task is not a PBI** (PBIs are containers and don't self-promote on their own import-stamped due — ADR 0016), (c) any of its subtasks is a **flagged subtask**, (d) any of its subtasks has `Due <= today` and is not done. (a) and (b) are *direct*; (c) and (d) are *virtual promotion* — the parent's frontmatter is untouched. Dismiss-for-today (`IUiStateService`) overrides all four. **PBI container grouping (ADR 0017) is layered *on top* of this rule and does not change it**: a PBI pulled into the My Day *view* only to host its in-My-Day children is a **container-only host**, not itself "in My Day" by this rule; conversely, a PBI that satisfies membership but has no actionable children is omitted from the view. See ADR 0008 (promotion model), ADR 0013 (date-scoped pins), ADR 0016 (PBI containers), ADR 0017 (cross-file container grouping). | on My Day, today's tasks |
| **Flagged subtask** | A subtask whose `IsMyDay == true` (frontmatter `my_day: true` or today's date). User-facing label only — the code surface stays `IsMyDay` / `my_day` for symmetry with the task-level field. A flagged subtask **virtually promotes** its parent into My Day; the flag itself is not written to the parent. See ADR 0008. | flagged sub, starred subtask, today subtask |
| **Virtual promotion** | The mechanism by which a task appears in My Day without `task.MyDay` being set — driven by task due-date, flagged subtasks, or due-soon subtasks. Distinguishes from **direct pinning** (user toggled `task.MyDay` to today's date). See ADR 0008. | implicit my-day, auto-promotion |
| **Direct pin** / **Scheduled pin** | Setting `task.MyDay` (or `subtask.MyDay`) to a specific date. A **direct pin** is when `my_day == today` (promotes into My Day now). A **scheduled pin** is when `my_day > today` (promotes on that future date). Past-dated pins (`my_day < today`) do not promote. Date-scoped per ADR 0013. "Remove from My Day" sets `my_day = null`. | pin, pinned, scheduled for |
| **Today's subtasks** | Within a parent rendered on My Day, the subset of its subtasks that render beneath it: `(IsMyDay \|\| Due <= today) && Status != done`. A directly-pinned parent with no qualifying subtasks renders only its segmented progress bar — no subtask list beneath. See ADR 0008. | flagged subtasks list (avoid: that name belongs to the deprecated separate section), today's steps |
| **Today's children** | Within a **PBI container** on My Day, the subset of its **cross-file** child Tasks (separate vault files, linked by `parent:`) that are themselves **In My Day today** and render nested beneath the PBI. The parent link may be the PBI's Glasswork Task ID or its ADO work-item ID/URL when the PBI is present in the vault. Carried on the model as the transient `GlassworkTask.TodaysChildren`, parallel to **Today's subtasks** (which are the PBI's own *in-file* checklist subtasks). Populated by `MyDayContainerGrouper`. See ADR 0017. | child rows, nested tasks (avoid "subtasks" — those are in-file) |
| **PBI container** | A **PBI** rendered on My Day as a card hosting actionable **Today's subtasks** and/or **Today's children**. A PBI with no actionable children is omitted even when directly pinned. A PBI with cross-file Today's children is pulled into the view to host them even if it does not independently promote (a **container-only host**) — grouping is presentation-only and never changes the promotion rule. Standalone rows sort before PBI containers. The container suppresses the leaf "complete" affordance (you complete its children) and reuses `IsManuallyCollapsed` to collapse/expand. See ADR 0017 (and ADR 0016 for the PBI/container concept). | container card, parent group (avoid "group header" — that is the Backlog shape, deliberately not used here) |
| **Backlog** | Page showing tasks not done and not on My Day. Includes a dedicated blocked board column / list section so Blocked Tasks remain visible without being mixed into the Ready backlog. | inbox, queue, anytime |
| **Work Log** | Page showing completed tasks. | done, archive, logbook, completed |
| **Active task** | A task that has rich state worth surfacing in the row — at least one subtask, a blocker, or a body summary. Renders as a **card** by default. | rich task |
| **Quiet task** | A task with no rich state to surface (no subtasks, no blocker, empty body). Renders as a **single-line row**. Cannot be expanded — there is nothing to expand. | simple task, plain task |
| **Adaptive row** | The list-row template that automatically picks card form vs. single-line form based on whether the task is active or quiet. | smart row, dynamic row |
| **Card form** | The expanded row rendering: title row + segmented progress bar + current-step + (optional) blocker row + (optional) blurb row. | expanded row, big row |
| **Single-line form** | The compact row rendering: title row only. | collapsed row, compact row, condensed row |
| **Collapsed** | A user-overridden state on an active task that forces it to render in single-line form even though it would otherwise be a card. **Asymmetric**: only active tasks can be collapsed; quiet tasks have no expand state. Persists across navigation and restarts via `IUiStateService`. | hidden, minimized, folded |
| **Segmented progress bar** | The per-subtask visual: one segment per subtask, colored by subtask status (done = accent, in-progress = lighter accent, blocked = red, dropped = gray, todo = empty outline). Falls back to a continuous bar with `n of m done` text when subtask count exceeds 12. | progress chart, status bar, subtask chart |
| **Current step** | The `Title` of the first subtask in `in_progress` status. Shown to the right of the progress bar in card form. | active step, current subtask, on-deck |
| **Blocker row** | Conditional row in card form, rendered only when at least one subtask is `blocked`. Shows the blocker subtask's title or first line of its notes, prefixed with a red 🚫. | block row, stuck row |
| **Blurb** | A one-line summary of what a task is about, shown in card form below the progress/blocker rows. **Source today**: first non-blank line of the task `Description` (with leading `#`, `>`, and link wrappers stripped, truncated at 80 chars). Never sourced from `Notes` or Artifacts — only from `Description`. **Future extension**: explicit `summary:` frontmatter field, when present, takes precedence. | summary line, blurb (term is fine; just don't confuse with the future `summary:` field) |
| **Chip** | A small inline metadata badge on the title row. Three kinds today: priority chip, due chip, ADO chip. | tag (tag is reserved for vault tags), pill, badge |
| **Priority chip** | Title-row chip showing task priority (`low`, `med`, `high`, `urgent`). Color-coded. Hidden when priority is unset. | — |
| **Due chip** | Title-row chip showing relative due date (`overdue` red, `today` orange, `≤ 3 days` accent, `future` neutral). Hidden when no due date. | due date, deadline |
| **ADO chip** | Title-row chip showing linked Azure DevOps work item (`ADO #1234`). Hidden when no ADO Link. Click jumps to ADO. Driven by the derived `AdoLink` projection over `Links[type=ado]`; legacy `ado_link` is migration input only. | work item link, ado link |
| **Empty state** | The visual rendered when a page has no tasks to show. Headline + sub copy + up to 2 CTAs. One reusable `EmptyState` control covers all pages. | placeholder, blank state, zero state |
| **Footer status bar** | A thin (~28px) strip at the bottom of `MainWindow` showing vault path, task counts, watcher state, and last-reload time. | status strip, status line, footer |
| **UI state** | Persistent app-local user preferences that **do not belong in the vault**. Stored in `%LocalAppData%\Glasswork\ui-state.json` via `IUiStateService`. Examples: collapsed task ids, future sidebar pane state. | preferences (reserved for actual user settings), settings (reserved for the Settings page), local state |
| **Self-write** | A vault file write originated by Glasswork itself. Tracked by `SelfWriteCoordinator` so the file watcher doesn't treat it as an external edit. | own write, internal write |
| **Home Dashboard** *(future)* | A planned future surface aggregating tasks plus non-task wiki notes from the vault. **Not built yet.** `HomePage` is being deleted in the current slice; a future dashboard will be a fresh design, not a revival. | home (use only with the "Dashboard" suffix to avoid ambiguity with the deleted `HomePage`) |
| **Inbox** *(deferred)* | The common todo-app concept of a triage queue for new tasks. **Not in Glasswork.** Backlog plays a similar role today. If/when added, would sit above Backlog. | triage, queue, new |
| **Vault Markdown View** | The single `UserControl` (`VaultMarkdownView` in `Glasswork.App.Controls`) that renders every markdown surface in the app — artifact bodies and Notes (read mode). Exposes a `Markdown` dependency property and a `LinkClicked` routed event. Vault-aware: knows how to resolve `[[wiki-links]]`, route through `ArtifactLinkPolicy`, and hand off to `IObsidianLauncher`. See ADR 0006. | MarkdownView, MarkdownArtifactView (the original ADR 0003 name; retired), MarkdownTextBlock (the pre-#71 attached-property shape; deleted) |
| **Wiki link** | A `[[stem]]` or `[[stem\|display]]` reference inside rendered markdown. Parsed with `BacklinkIndex`'s canonical regex. In `VaultMarkdownView`, clicks resolve as follows: a Glasswork task (`*.md` under `wiki/todo/`) → in-app navigate; any other vault page → open in Obsidian; unresolved → muted, non-interactive. Anchors `[[stem#section]]` are v2. See ADR 0006 §3. | wikilink (no space), internal link, double-bracket link (all fine in prose; "wiki link" is canonical in code and docs) |
| **Callout** | An Obsidian-style blockquote with a type marker — `> [!note]`, `> [!warning]`, `> [!tip]`, `> [!important]`. Rendered by `VaultMarkdownView` as a themed `Border` around the inner block content. In v1 callouts are always expanded; Obsidian's foldable `> [!note]-` / `> [!note]+` syntax is honored as a plain callout (the `+`/`-` suffix is ignored). Unknown callout types fall back to a plain blockquote. Foldable state is v2. | admonition, alert box, aside |
| **Notes read mode** | The default rendering of a task's Notes section in TaskDetail — `VaultMarkdownView` with the Notes markdown. Rendered markdown is clickable (links routed via `ArtifactLinkPolicy`), selectable, but not directly editable. Toggle to edit mode via the Edit button or `Ctrl+E`. | rendered notes, notes view |
| **Notes edit mode** | The `TextBox` editing surface for Notes. Entered via the Edit button or `Ctrl+E`; exited via Done (saves and returns to read mode) or `Esc` (discards the in-memory buffer and returns). Debounced autosave continues to fire while typing. Only one of read/edit is visible at a time. See ADR 0006 §4. | notes editor, edit toggle |
| **Notes conflict banner** | `InfoBar` shown at the top of the Notes section when the underlying task file is changed externally **while** the user is in edit mode **with** unsaved divergent changes. Three actions: Discard mine and reload, Keep mine and overwrite on save, Open Obsidian to merge. Prevents silent loss of agent writes. See ADR 0006 §5. | merge banner, conflict bar |
| **Obsidian launcher** | `IObsidianLauncher.Open(vaultRelativePath)` in `Glasswork.Core.Services`. Builds an `obsidian://open?vault=<name>&file=<path>` URI and hands it to `Windows.System.Launcher.LaunchUriAsync`. The vault name is the leaf of the configured vault-root path. Returns `Task<bool>` — `true` = launched, `false` = fallback triggered (`InfoBar` asking the user to install Obsidian, shown once per session). Shared primitive: used by wiki-link clicks, the Backlinks section, and future #68 affordances. See ADR 0006 §6. | obsidian link, obsidian uri launcher |
| **Task search** | Querying the vault for tasks whose content matches a free-text topic query. Implemented in `TaskSearchService` (Core) and exposed as the `search_tasks` MCP tool. Distinct from `list_tasks` (structural enumeration with status/parent filters). Searches title, description, notes, subtasks, and tags by default; artifact body content is **not** searched in v1. | keyword search, full-text search, task lookup |
| **Matched-in** | The set of task fields in which a search query matched — returned per-hit by `search_tasks` as the `matched_in` JSON array. Valid values in v1: `title`, `description`, `notes`, `subtasks`, `tags`. Used by agents to know where the relevant content lives without re-reading the full task. | match fields, hit fields |
| **Snippet** | A short excerpt (~120 chars) extracted from the highest-priority matched field of a search hit, returned as the `snippet` string by `search_tasks`. Lets agents scan relevance without calling `get_task`. Always sourced from a task prose field (never from artifact body content). Prefixed/suffixed with `...` when the excerpt is mid-field. | excerpt, extract, context |
| **Update check** | The act of asking whether a newer Glasswork version exists: an unauthenticated HTTPS read of the public GitHub API's latest release `tag_name`, compared against the Installed Version. Runs once in the background at startup and on demand from Settings. Detection only — never builds or installs anything. See ADR 0011. | version check, update poll |
| **Installed version** | The version of Glasswork currently running, read from the `AssemblyInformationalVersion` attribute (the same value the footer status bar shows). The left-hand side of every Update check comparison. | current version, running version, app version |
| **Available version** | The latest version published as a GitHub release tag (e.g. `v1.4.0` → `1.4.0`). The right-hand side of an Update check. An update is available when Available Version > Installed Version by SemVer. | latest version, remote version, release version |
| **Release publication** | The deliberate repo-maintenance action that creates a GitHub Release tag (`vX.Y.Z`) for a chosen commit, making that version visible to Update checks. | PR merge, deploy, publish (reserved for `publish.ps1`) |
| **Release PR** | An agent-prepared PR that bumps the app version recorded in `Glasswork.csproj` and commits Release notes before Release publication; it is the audit/checks surface and may be auto-merged when clean. | release commit, version-only merge |
| **Release notes** | The human-readable markdown summary for a published version, committed by the Release PR at `docs\releases\vX.Y.Z.md` and used as the GitHub Release body. | changelog, generated notes |
| **Release workflow** | The deterministic GitHub Actions workflow that validates a requested version against `Glasswork.csproj`, publishes `Glasswork-win-x64.zip` plus its SHA-256 sidecar, then creates the matching GitHub Release tag using agent-prepared Release notes. | release pipeline, deployment workflow, publish workflow |
| **Release package** | The self-contained `Glasswork-win-x64.zip` attached to every GitHub Release. It is the immutable payload consumed by Self-update and is paired with a `.sha256` sidecar. | binary asset, update archive, release archive |
| **Self-update** | The apply action behind "Restart to update": Glasswork spawns the detached Updater, closes itself, and the Updater verifies and installs the Release package before relaunching. Distinct from the Update check (detection only). The release page remains visible while the update runs. See ADR 0020. | auto-update, in-app update |
| **Updater** | The bundled detached `Updater\release-update.ps1` script that performs a Self-update. Given the app PID, Installed Version path, and Available Version, it downloads the matching Release package and checksum, waits for Glasswork to exit, verifies, swaps with rollback, and relaunches behind an "Updating Glasswork…" progress window. | update script, updater process |
| **Repo Path** *(legacy)* | The local source-repository path previously stamped into UI State for ADR 0011's source-build Updater. ADR 0020 removed it from the active Self-update contract; retained state is ignored. | source path, repo location, build path |

## Naming conventions

- **Code symbols**: `PascalCase` for types, `camelCase` for parameters and locals, `_camelCase` for private fields. Match the term spelling exactly (`SubTask`, not `Subtask` or `Sub_Task`).
- **UI labels**: title case for headings (`My Day`), sentence case for sub-copy (`Pick something from your backlog.`).
- **Frontmatter keys**: `snake_case` (`my_day`, `links`, legacy `ado_link`, future `summary`).
