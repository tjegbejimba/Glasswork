## Summary

- Add opaque, versioned Resource Revisions to every MCP response that carries a Task or Task summary.
- Add the read-only `get_capabilities` contract handshake with implemented and future capability sets.
- Add isolated temporary-Vault MSTest coverage and document the MCP read contract.

## Decisions

- Resource Revisions use exact task-file bytes and a versioned `rr1-` token; callers compare tokens for equality and do not parse them.
- Capability discovery remains available when the Vault is unavailable because it does not read task data; Vault-dependent tools remain filtered by existing preconditions.
- Transactional mutations are reported as future capability only and are not introduced in this slice.

## Review notes

Both required reviews identified the same high-confidence issues: capability
discovery could not be invoked without a Vault, and revisions were calculated
from a second disk read. Both are fixed by moving `get_capabilities` to a
Vault-independent tool type and retaining the exact bytes used by
`VaultService` reads for revision calculation. The search fallback regression
was also restored.

The reviews also requested the PRD-aligned named capability set, the breaking
`0.7.0` package bump, changelog entry, and explicit ADR/glossary amendments;
all are included. Deferred mutation-result revisions and the currently dead
in-progress activity shape remain out of scope for this read-only slice.
